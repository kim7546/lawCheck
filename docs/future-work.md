# lawCheck 후속 작업 목록

작성 기준일: 2026-09-20

기준 문서: [MVP 기획서 v0.4](legal_ai_platform_solution_plan_v0.4.md), [DB 설치·Railway 설정](database-setup.md), [기존 배포 안내](railway-deployment.md).

체크박스는 구현과 해당 항목의 검증이 모두 끝났을 때 완료 처리합니다. 아래 순서는 권장 진행 순서이며, 기획서와 이후 확정된 사용자 요구사항을 함께 적용합니다.

## 현재 완료 범위

- [x] FO·BO·API 프로젝트와 기본 화면 구성.
- [x] OpenAI 질문·답변 API 및 법률 질문 여부에 따른 검증 요청 버튼 표시.
- [x] FO Enter 전송, 입력창 초기화, 최근 대화 스크롤, 응답 대기 점 애니메이션.
- [x] 개발 중 세션당 3회 제한 비활성화.
- [x] PostgreSQL 16개 테이블의 Prisma 스키마·migration·초기 사무실 seed 구성.
- [x] 사무실·세션 소속, 검증 원문 스냅샷, 중복 요청, 배정 버전, 이력 수정 방지 등 DB 제약 작성.
- [x] 로컬 Docker Compose와 Railway DB 포함 API Docker 배포 설정 작성.
- [x] 격리된 PostgreSQL 엔진의 migration·무결성 테스트, 타입 검사·lint·API 테스트·빌드 통과.

**실제 API 서버의 세션·질문·답변 DB 저장 코드를 연결했습니다. Docker·Railway의 실제 DB 실행 검증과 FO 화면 복원은 남아 있습니다. 검증 요청·BO 화면은 체험 기능입니다.**

## 1. 로컬 DB와 Railway 실행 확인 — 최우선

- [ ] PC에 Docker Desktop을 설치하고 WSL 2/Linux 컨테이너 실행 확인.
- [ ] 기존 `.env`를 보존하면서 DB 접속 정보 설정.
- [ ] `npm run db:up`, `npm run db:setup`, `npm run db:status` 실행.
- [ ] `npm run db:test`로 실제 로컬 PostgreSQL의 제약 검사.
- [ ] Prisma Studio에서 16개 테이블과 초기 사무실 확인.
- [ ] 컨테이너 중지·재시작 후 데이터 유지 확인.
- [ ] API Docker 이미지의 빌드·실행과 Prisma 실제 접속 확인.
- [ ] Railway에 PostgreSQL 서비스를 생성하고 API에 `DATABASE_URL` 참조 설정.
- [ ] API Config File을 `/apps/api/railway.database.json`으로 변경하고 배포.
- [ ] pre-deploy migration·seed 성공 및 `npm run db:check` 확인.
- [ ] FO·BO의 `API_PROXY_TARGET`, API 도메인·포트 확인 및 기존 채팅 회귀 검사.

완료 기준: 로컬과 Railway 모두 DB 연결·migration·seed가 성공하고 재시작 후 데이터가 유지된다. HTTP health 200만으로 DB 연결 완료 처리하지 않는다.

## 2. API 공통 DB 접근과 익명 세션 저장

- [ ] Prisma Client의 공통 생명주기, 종료 처리, DB 오류 응답 구현.
- [ ] 환경별 DB 연결 수·시간 제한 설정 및 접속 실패 로그 정리.
- [ ] API에서 사무실 귀속을 결정하고 모든 조회·변경에 소속 조건 적용.
- [x] 익명 세션 생성·조회·만료·새 대화 시작을 `chat_sessions`에 연결.
- [ ] 쿠키 토큰 원문 대신 해시 저장, 쿠키 보호 속성과 만료 처리 구현.
- [ ] 질문 수·동시 요청 제어를 DB 트랜잭션으로 전환.
- [x] 개발에서는 `QUESTION_LIMIT_ENABLED=false`와 무제한 세션 정책 유지.
- [ ] 다른 세션·사무실 데이터 접근 및 서버 재시작·복수 인스턴스 시나리오 검사.

완료 기준: API 재시작 후에도 유효한 세션을 인식하고 세션·사무실 간 데이터 접근을 차단한다.

## 3. FO 질문·답변 기록 저장과 복원

- [x] 사용자 질문·AI 답변·비법률 안내·실패 상태를 `chat_messages`에 저장.
- [ ] 질문과 답변의 부모 관계, 대화 순서, 재시도용 요청 키 관리.
- [ ] 중복 클릭·네트워크 재시도 시 질문과 답변의 중복 저장 방지.
- [ ] OpenAI 실패·시간 초과·프로세스 중단 시 미완료 메시지 복구 정책 구현.
- [ ] DB에서 현재 세션의 대화 내역을 조회하는 API와 FO 복원 기능 구현.
- [ ] 새 대화 시작 시 이전 대화와 새 세션 구분.
- [x] 모델 호출에 사용하는 이전 대화를 서버에서 조회하고 최근 완료 대화 10쌍으로 제한.
- [ ] 외부 모델 호출 전에 개인정보 탐지·마스킹 적용.
- [ ] 모델·지연·토큰 사용량·실패 코드 기록 범위 결정 및 민감정보 없는 운영 로그 구현.
- [ ] 로컬·Railway에서 줄바꿈, 입력창 초기화, 최근 대화 스크롤, 대기 애니메이션 회귀 검사.
- [ ] 답변 길이와 무조건적인 변호사 상담 권유 여부를 프롬프트·출력 처리 기준으로 점검.

완료 기준: 새로고침·API 재시작 후 질문과 답변이 복원되고, 실패·재시도 시 중복 기록이 생기지 않는다.

## 4. FO 변호사 검증 요청 API

- [ ] 체험용 검증 요청 폼을 실제 API에 연결.
- [ ] 이메일·추가 설명 입력 검증과 필요한 개인정보 고지·동의 반영.
- [ ] 서버에서 세션 소유권과 선택한 질문·완료된 법률 답변 관계 검증.
- [ ] 요청·원문 스냅샷·처리 기한을 저장하고 접수 결과 반환.
- [ ] 같은 답변에 대한 중복 요청·재시도를 일관되게 처리.
- [ ] 비법률·분류 실패·미완료·오류 답변에 대한 직접 API 요청도 거절.
- [ ] 현재 세션이 소유한 검증 요청의 상태 조회 및 FO 표시 구현.
- [ ] 브라우저 세션 만료와 검증 업무 처리 기한을 분리.

완료 기준: 본인의 완료된 법률 답변에만 검증을 요청할 수 있고, 새로고침 후에도 접수 상태를 확인할 수 있다.

## 5. BO 로그인·직원 권한·변호사 관리

- [ ] 초기 관리자 seed 계정의 비밀번호 해시 검증과 로그인·로그아웃 구현.
- [ ] 직원 세션 저장·만료·폐기, 로그인 시도 제한 구현.
- [ ] 관리자·배분 담당자·변호사의 역할별 API 및 화면 권한 적용.
- [ ] 직원 등록·상태 변경·비밀번호 변경/초기화 흐름 구현.
- [ ] 변호사 등록·승인·활성 상태·배정 가능 여부·메일 수신 설정 구현.
- [ ] 입퇴사 기간 등록·수정과 효력 시각 처리 구현.
- [ ] 휴가 등록·승인·취소와 기간 중복 업무 표시 구현.
- [ ] 퇴사·계정 정지 시 기존 로그인 세션과 검토 권한 차단.
- [ ] 관리 변경과 처리 주체를 `audit_logs`에 기록.

완료 기준: 소속과 역할에 따라 접근을 제한하고, 자격이 없는 변호사를 배정 후보에서 제외한다.

## 6. BO 검증 업무 배정·회수·재배정

- [ ] 요청 목록·상세·상태·기간·담당자 검색과 페이지네이션 구현.
- [ ] 승인·재직·휴가·활성 상태에 따른 배정 가능 여부 검사.
- [ ] 배정·재배정을 요청 상태, 버전, 이력, 초대, outbox와 같은 트랜잭션으로 저장.
- [ ] 동시 배정 요청 시 현재 버전 확인과 충돌 응답 구현.
- [ ] 재배정 시 이전 초대·검토 세션 무효화 및 미발송 초대 작업 취소.
- [ ] 배정 해제·반려·만료 등 기획서의 상태 전이 구현.
- [ ] 휴가 시작·퇴사 효력 발생 시 미완료 업무 회수와 BO 재배정 대기 표시.
- [ ] 완료된 요청의 재배정 차단, 배정 사유·담당자 변경 이력 표시.
- [ ] 미배정·기한 임박·기한 초과 업무 표시.

완료 기준: 동시 요청에도 담당자가 한 명으로 확정되고, 이전 담당자의 링크·답변 권한이 즉시 사라진다.

## 7. 변호사 검토 링크와 답변 제출

- [ ] 담당자별 초대 토큰 발급·해시 저장·만료 처리 구현.
- [ ] 링크 접근 시 현재 배정 버전·담당자 자격·만료·폐기 여부 검사.
- [ ] 요청 하나에 한정된 검토 세션 발급 및 권한 검사.
- [ ] 검토 수락과 `REVIEWING` 상태 전환 구현.
- [ ] 질문·AI 답변 스냅샷·추가 설명을 검토 화면에 표시.
- [ ] 검증 결과 유형과 답변 본문 검증 및 제출 기능 구현.
- [ ] 답변·요청 완료·사용자 메일 outbox를 같은 트랜잭션으로 저장.
- [ ] 이중 제출·재배정과 동시 제출·만료 직전 제출 경쟁 조건 검사.
- [ ] 제출 완료 후 본문 수정 차단 및 결과 표시.

완료 기준: 현재 유효한 담당자만 한 번 답변하며, 완료 처리와 메일 발송 예약이 함께 저장된다.

## 8. 이메일 발송과 재시도 worker

- [ ] 이메일 제공자·발신 도메인 설정과 발신 인증 완료.
- [ ] 변호사 초대·사용자 답변 메일 템플릿과 링크 구성.
- [ ] outbox worker 실행 방식과 Railway 배포 설정 작성.
- [ ] 작업 잠금·lease·재시도 간격·최대 횟수·실패 상태 처리.
- [ ] 발송 시도마다 `email_delivery_attempts` 기록.
- [ ] 재배정·회수·만료된 초대의 발송 차단.
- [ ] 임시 초대 payload 암호화·키 관리 및 완료·취소·만료 시 삭제.
- [ ] 제공자 응답 유실·중복 작업·worker 재시작에 대한 중복 발송 완화.
- [ ] BO 발송 이력·실패 사유·권한 있는 재시도 기능 구현.

완료 기준: 발송 실패를 추적·재시도할 수 있고, 유효하지 않은 검토 링크를 새로 발송하지 않는다.

## 9. 운영 준비와 공개 전 확정 사항

- [ ] 개인정보 고지·동의 방식, 이메일 소유 확인 적용 여부 확정.
- [ ] 대화·검증·메일·감사 기록의 보관기간과 삭제·익명화 절차 확정 및 구현.
- [ ] 세션·초대 만료 시간, 검증 처리 기한, 메일 재시도 한도 확정.
- [ ] 사무실별 AI 사용 비용 상한과 제한 시 사용자 안내 구현.
- [ ] 운영 비밀값 관리, 로그의 이메일·대화 원문·토큰 URL 노출 점검.
- [ ] 쿠키 인증 요청의 CSRF 방어, 입력 제한, 요청 속도 제한 검증.
- [ ] DB 백업 일정·보관 정책 설정 및 별도 환경에서 복원 훈련.
- [ ] DB·API·메일 장애 알림과 요청 지연·실패율·미배정 업무 모니터링.
- [ ] FO·BO의 Vite preview를 운영용 정적 파일 서버·API 프록시로 전환.
- [ ] migration 실패 대응, 배포 복구, 운영 점검 절차 문서화.
- [ ] **오픈 시에만** 세션당 3회 제한 활성화 및 기존 무제한 세션 전환 정책 적용.

완료 기준: 정책값과 장애 대응 방법이 문서화되고 실제 배포 환경에서 동작한다. 개발 중에는 3회 제한을 다시 켜지 않는다.

## 10. 통합 검증과 MVP 완료 판정

- [ ] FO 질문 → DB 저장 → 검증 요청 → BO 배정 → 변호사 답변 → 사용자 이메일 전체 흐름 검사.
- [ ] 타 사무실·타 세션·비담당자 접근 거절 검사.
- [ ] 중복 요청·동시 배정·재배정과 답변 제출 경쟁 조건 검사.
- [ ] 휴가·퇴사·정지·만료 후 기존 링크와 세션 사용 차단 검사.
- [ ] DB·OpenAI·메일 장애 및 API·worker 재시작 후 복구 검사.
- [ ] Railway 재배포 이후 대화·업무·발송 이력 보존 검사.
- [ ] 데스크톱·모바일 FO·BO 주요 사용자 흐름 E2E 검사.
- [ ] 기획서 13장의 MVP 완료 기준 전체를 구현·테스트 결과와 대조.
