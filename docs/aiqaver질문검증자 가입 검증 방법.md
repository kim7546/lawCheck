# AIQAVER 질문검증자 가입 검증 방법

## 1. 목적

AIQAVER의 질문검증자는 사용자에게 전문가의 답변 또는 검증 결과를 제공하는 역할을 한다.  
따라서 단순 회원가입만으로 검증자 권한을 부여하지 않고, 실제 자격을 보유한 전문가인지 확인하는 절차가 필요하다.

특히 변호사의 경우 다음 세 가지를 구분하여 확인해야 한다.

1. 가입한 사람이 실제 본인인지
2. 실제 변호사 자격 및 등록 상태가 존재하는지
3. 현재 정상적으로 활동 가능한 상태인지

AIQAVER의 전문가 인증은 단순 자격증 파일 업로드가 아니라 다음 절차를 결합하는 방식으로 설계하는 것이 바람직하다.

> 본인확인 → 전문가 자격 확인 → 현재 상태 확인 → 소속 확인 → 관리자 승인 → 정기 재검증

---

## 2. 변호사 검증 시 확인해야 할 핵심 항목

| 검증 항목 | 확인 내용 |
|---|---|
| 본인 확인 | 가입자가 실제 해당 인물인지 |
| 변호사 등록 확인 | 대한변호사협회 등에 정상 등록된 변호사인지 |
| 현재 활동 상태 | 휴업, 등록취소 등 활동상 문제가 없는지 |
| 소속 확인 | 법무법인, 법률사무소 등 신고된 소속과 일치하는지 |
| 제출 서류 진위 | 등록증명원, 변호사 신분증 등이 위조되지 않았는지 |
| 전문분야 확인 | 특정 전문분야를 표시하는 경우 공식 등록 여부 |
| 정기 재검증 | 최초 인증 후 상태 변경 여부를 주기적으로 확인 |

---

# 3. 변호사 자격을 검증할 수 있는 방법

## 3.1 대한변호사협회 변호사 검색

가장 기본적인 확인 방법이다.

가입 신청자가 입력한 다음 정보를 대한변호사협회 등의 공식 변호사 검색 서비스에서 대조한다.

- 성명
- 변호사 등록번호
- 소속 법무법인 또는 법률사무소
- 사무실 주소
- 공개된 연락처

### 장점

- 초기 서비스에서도 쉽게 적용 가능
- 별도 시스템 개발 없이 관리자 수동 확인 가능
- 실제 등록된 변호사인지 1차 확인 가능

### 한계

동명이인 또는 다른 변호사의 정보를 도용할 가능성이 있으므로 이것만으로는 충분하지 않다.

---

## 3.2 휴대전화 본인인증

PASS 등 본인확인 서비스를 통해 실명과 휴대전화 명의자를 확인한다.

확인 가능한 정보의 예:

- 성명
- 생년월일
- 휴대전화 본인 여부
- 본인확인 식별정보

이후 본인인증 결과와 전문가 등록정보를 대조한다.

### 예시

```text
휴대전화 본인확인

홍길동 / 1985년생
        ↓

대한변호사협회 등록정보

홍길동 / 1985년생
        ↓

일치 여부 확인
```

타인의 변호사 정보를 이용한 가입을 막기 위해 필수에 가까운 절차로 사용하는 것이 좋다.

---

## 3.3 변호사등록증명원 제출

전문가 가입 신청자에게 최근 발급된 변호사등록증명원을 제출하도록 한다.

권장 기준 예시:

> 최근 30일 이내 발급된 변호사등록증명원

제출 항목:

- 변호사등록증명원 PDF 또는 이미지
- 발급일
- 등록번호
- 성명

### 장점

단순 자격증보다 현재 등록 상태를 확인하기 좋다.

AIQAVER 1차 오픈 단계에서는 관리자 수동 검수 방식으로 충분히 활용할 수 있다.

---

## 3.4 등록증명원 진위 확인

제출된 PDF나 이미지 자체만 믿지 않고 공식 진위확인 서비스를 통해 확인하는 절차를 추가한다.

```text
제출된 등록증명원
        ↓
공식 진위 확인
        ↓
내용 일치
        ↓
AIQAVER 전문가 인증 승인
```

이를 통해 위조 또는 변조된 서류 제출 위험을 줄일 수 있다.

---

## 3.5 변호사 신분증 확인

대한변호사협회에서 발급하는 변호사 신분증을 보조적인 인증수단으로 활용할 수 있다.

가입 시 받을 수 있는 정보의 예:

- 변호사 신분증 이미지
- 발급번호
- 성명
- 등록번호

가능하면 신분증을 단순 업로드 받는 것에서 끝내지 않고 공식 진위확인 방법과 함께 사용한다.

---

## 3.6 본인 얼굴 또는 셀피 인증

보안을 더 강화하려는 경우 가입 직후 얼굴 촬영을 요구할 수 있다.

```text
변호사 신분증 사진
        +
실시간 얼굴 촬영
        ↓
본인 일치 확인
```

다만 얼굴정보는 민감한 개인정보 관리 부담이 커질 수 있으므로 초기 서비스에는 과도할 수 있다.

따라서 1차 오픈에서는 선택사항 또는 추후 고도화 기능으로 두는 것이 적절하다.

---

## 3.7 소속 법무법인 또는 법률사무소 확인

가입자가 입력한 소속 정보를 공식 변호사 등록정보와 비교한다.

예:

```text
가입 신청 정보

홍길동
법무법인 ABC

        ↓

공식 변호사 등록정보

홍길동
법무법인 ABC

        ↓

MATCH
```

확인할 항목:

- 소속 법무법인/사무소명
- 주소
- 대표 전화번호
- 공개 이메일

---

## 3.8 사무실 이메일 인증

법무법인이나 법률사무소의 공식 도메인 이메일을 사용하는 경우 추가 인증수단으로 활용할 수 있다.

예:

```text
hong@abclaw.co.kr
```

해당 이메일로 인증코드를 발송하여 소속 여부를 보조적으로 확인한다.

다만 개인변호사의 경우 Gmail, Naver 등 일반 이메일을 사용할 수 있으므로 필수 조건으로 설정하지 않는 것이 좋다.

---

## 3.9 사무실 전화 확인

고위험 또는 추가 확인이 필요한 가입 신청은 운영자가 공개된 사무실 대표번호로 직접 확인할 수 있다.

중요한 점은 신청자가 임의로 입력한 번호가 아니라 가능한 경우 공식적으로 공개된 번호를 사용해야 한다는 것이다.

---

## 3.10 사업자등록 상태 확인

개인 법률사무소 또는 법무법인 운영 여부를 추가로 검증하고자 하는 경우 사업자등록정보를 확인할 수 있다.

활용 가능 정보:

- 사업자등록번호
- 대표자명
- 개업일자
- 계속사업 여부
- 휴업 여부
- 폐업 여부

향후 국세청 사업자 상태조회 API 등을 연계하면 자동화가 가능하다.

단, 사업자등록 확인은 변호사 자격 자체를 증명하는 수단은 아니고 사무실 또는 사업체 확인을 위한 보조수단이다.

---

## 3.11 징계정보 확인

전문가 신뢰도를 높이기 위해 법령과 운영정책이 허용하는 범위에서 공개된 징계정보를 확인하는 방법도 고려할 수 있다.

다만 다음과 같은 단순한 정책은 피하는 것이 좋다.

> 징계 이력이 존재하면 무조건 가입 불가

징계 종류, 기간, 현재 효력, 공개 가능 범위, 개인정보 및 관련 법적 문제를 별도로 검토해 운영정책을 수립해야 한다.

---

## 3.12 전문분야 등록 확인

AIQAVER 프로필에서 다음과 같이 특정 전문분야를 강조하려는 경우 별도의 검증이 필요하다.

- 형사 전문
- 이혼 전문
- 부동산 전문
- 가사 전문
- 행정 전문

전문분야가 공식적으로 등록된 것인지 단순 자기소개인지 구분한다.

### 표시 예시

```text
홍길동 변호사

✓ 변호사 인증
✓ 형사 분야 공식 등록 확인

관심분야
- 부동산
- 스타트업
```

이를 통해 사용자가 공식 전문등록과 단순 경험/관심분야를 혼동하지 않도록 한다.

# 4. AIQAVER 1차 오픈 권장 인증 절차

초기에는 지나치게 복잡한 자동화를 만들기보다 관리자 승인 기반으로 시작하는 것이 현실적이다.

## 가입 절차

```text
전문가 회원가입
        ↓
전문가 유형 선택
        ↓
휴대전화 본인인증
        ↓
성명 / 생년월일
        ↓
변호사 등록번호 입력
        ↓
변호사등록증명원 업로드
        ↓
소속 법무법인/사무실 입력
        ↓
변호사 신분증 정보 또는 추가자료
        ↓
인증 신청
```

## 관리자 검증 절차

```text
인증 신청 접수
        ↓
본인인증 결과 확인
        ↓
공식 변호사 등록정보 조회
        ↓
등록번호 / 성명 비교
        ↓
소속 사무실 비교
        ↓
등록증명원 진위 확인
        ↓
필요 시 신분증/사무실 추가 확인
        ↓
관리자 승인
        ↓
AIQAVER 인증 전문가
```

---

# 5. 사용자에게 보여줄 인증 표시

사용자에게 내부 인증과정을 전부 노출할 필요는 없다.

예:

```text
홍길동 변호사

✓ AIQAVER 전문가 인증

대한변호사협회 등록정보 확인
최근 인증일: 2026.09.25
```

또는 세부 인증을 표시한다.

```text
✓ 본인확인
✓ 변호사 자격확인
✓ 소속확인
```

---

# 6. 인증 등급 설계

AIQAVER 내부적으로는 다음과 같이 나눌 수 있다.

| 등급 | 의미 |
|---|---|
| 본인확인 | 휴대전화 등으로 실제 가입자 확인 |
| 자격확인 | 변호사 등록 및 관련 증명 확인 |
| 소속확인 | 법무법인/사무소 정보 확인 |
| 고급확인 | 추가 서류, 전문분야, 사업자정보 등 확인 |

사용자 화면에는 복잡한 등급 대신 `AIQAVER 인증 전문가`와 세부 인증 배지를 보여주는 방식이 적절하다.

# 7. 정기 재검증

전문가 자격은 최초 가입 당시만 확인하고 끝내서는 안 된다.

향후 다음과 같은 변화가 발생할 수 있다.

- 휴업
- 폐업
- 소속 변경
- 사무실 이전
- 등록상태 변경
- 전문분야 등록 변경
- 징계 또는 자격 관련 상태 변경

따라서 일정 주기로 재인증하는 구조가 필요하다.

### 권장 예시

```text
2026.09.25
최초 인증
        ↓
1년 후
        ↓
재인증 요청
        ↓
최신 등록증명원 제출
        ↓
관리자 검토
        ↓
2027.09.25 인증 갱신
```

초기에는 **연 1회 재인증** 정도가 현실적이다.

중요한 정보가 변경된 경우 즉시 재검증하도록 정책을 둘 수도 있다.

# 8. DB 설계 방향

단순히 다음과 같이 저장하면 부족하다.

```text
role = LAWYER
```

전문가 자격 자체를 별도 데이터 구조로 관리하는 것이 좋다.

예:

```text
expert_type = LAWYER

identity_verified = true

license_verified = true
license_number = XXXXX
license_verified_at = 2026-09-25

office_verified = true

verification_method =
KBA_REGISTRATION_CERTIFICATE

verification_status = VERIFIED

reverification_due_at = 2027-09-25
```

추가로 다음 상태값을 사용할 수 있다.

```text
PENDING
UNDER_REVIEW
VERIFIED
REJECTED
REVERIFICATION_REQUIRED
SUSPENDED
EXPIRED
```

# 9. ExpertCredential 구조 권장

AIQAVER는 향후 변호사 외에도 다음 전문가를 추가할 가능성이 있다.

- 세무사
- 공인회계사
- 공인노무사
- 변리사
- 의사
- 약사
- 입시전문가
- 부동산 전문가
- 기타 전문 자격 보유자

따라서 변호사 전용 테이블만 만드는 것보다 전문가 자격을 공통 구조로 관리하는 것이 좋다.

예:

```text
Expert
 ├─ ExpertCredential
 │    ├─ credentialType
 │    ├─ credentialNumber
 │    ├─ issuingOrganization
 │    ├─ verifiedAt
 │    ├─ expiresAt
 │    ├─ status
 │    └─ verificationMethod
 │
 ├─ ExpertOrganization
 │    ├─ organizationName
 │    ├─ organizationType
 │    └─ verified
 │
 └─ ExpertVerificationHistory
      ├─ verifiedBy
      ├─ verificationDate
      ├─ result
      └─ memo
```

이렇게 만들어 두면 향후 전문가 종류가 늘어나더라도 동일한 인증 시스템을 활용할 수 있다.

---

# 10. 자동 크롤링 사용 시 주의사항

공식 변호사 검색 서비스의 정보를 프로그램이 대량으로 수집하거나 전체 변호사 데이터베이스를 복제하는 방식은 피하는 것이 좋다.

초기 서비스에서는 다음 방식을 권장한다.

```text
가입자가 인증 신청
        ↓
해당 가입자 정보만 개별 확인
        ↓
관리자 승인
```

향후 회원 수가 증가하면 해당 기관과의 정식 API 제공, 데이터 이용계약 또는 제휴 가능성을 검토한다.

# 11. AIQAVER 초기 권장 정책

## 필수

1. 휴대전화 본인확인
2. 성명/생년월일 확인
3. 변호사 등록번호 입력
4. 공식 등록정보 확인
5. 최근 변호사등록증명원 제출
6. 등록증명원 진위 확인
7. 소속 사무실 확인
8. 관리자 최종 승인

## 선택 또는 고도화 단계

1. 변호사 신분증 확인
2. 사무실 이메일 인증
3. 사무실 전화 인증
4. 사업자등록 상태 확인
5. 전문분야 등록 확인
6. 징계정보 확인
7. 실시간 얼굴 인증
8. 외부기관 API 연동

# 13. 결론

AIQAVER에서 변호사 검증은 단순한 자격증 업로드 방식으로 처리하면 안 된다.

가장 현실적인 초기 방식은 다음 네 가지를 결합하는 것이다.

> **본인인증 + 공식 변호사 등록 확인 + 최근 등록증명원 확인 + 관리자 승인**

이후 서비스가 성장하면 다음 단계로 확장한다.

> **소속 자동검증 + 사업자 API + 전문분야 검증 + 주기적 재인증 + 공식기관 API/제휴**

이 구조를 처음부터 `ExpertCredential` 중심으로 설계하면 향후 세무사, 노무사, 회계사, 변리사 등 다양한 검증자 유형을 동일한 시스템 안에서 확장할 수 있다.

## 참고 방향

실제 서비스 적용 전에 다음 기관의 최신 정책과 이용조건을 확인하는 것이 필요하다.

- 대한변호사협회
- 국가법령정보센터
- 개인정보보호위원회 / 개인정보 포털
- 국세청 / 공공데이터포털
- 본인확인기관(PASS 등)

특히 자격정보 자동수집, 증명서 보관, 생년월일·신분증·얼굴정보 등의 개인정보 처리와 관련해서는 개인정보처리방침과 보관기간, 접근통제, 파기정책을 함께 설계해야 한다.
