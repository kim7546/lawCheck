# Office 전문가 그룹과 가입 동의

전문가 그룹명·정렬순서·사용 여부는 [공통 코드 관리](common-codes.md)의 `EXPERT_GROUP` 그룹에서 조회합니다. 기존 전문가 그룹·요금제 Enum은 공통 코드 상세 외래키로 전환했으며, 값과 기존 회원의 미등록 상태는 보존합니다.

현재 Office는 변호사 그룹입니다. 요청에 열거된 네 직역을 기준으로 아래 코드를 추가했습니다.

| 코드            | 그룹   | 신규 가입 |
| --------------- | ------ | --------- |
| LAWYER          | 변호사 | 가능      |
| LABOR_ATTORNEY  | 노무사 | 준비 중   |
| PATENT_ATTORNEY | 변리사 | 준비 중   |
| TAX_ACCOUNTANT  | 세무사 | 준비 중   |

`GET /api/v1/bo/signup-policy`가 그룹과 가입 가능 여부, 필수 문안 및 버전을 제공합니다. 가입 화면과 서버 검증은 동일한 정책을 사용합니다. 그룹은 명시적으로 선택하며, 체크박스는 사전 선택하지 않습니다. 모두 동의와 개별 동의를 모두 지원합니다. 광고·마케팅 동의는 수집하지 않습니다.

신규 가입에는 `expertGroup`과 `consents: [{ kind, version, accepted: true }]`가 필요합니다. 필수 문안은 서비스 이용약관, 개인정보 수집·이용 동의, 전문가 활동 및 비밀유지 약정입니다. 누락·중복 항목·옛 버전·문자열 true·미지원 그룹은 서버가 거부합니다. 회원과 동의 기록은 하나의 트랜잭션으로 저장하며, 문안 원본과 버전, 서버 동의 시각을 남깁니다. 문안을 수정하면 반드시 버전을 올립니다.

## 기존 데이터

### 변호사 가입 양식

변호사 Office는 별도의 `LawyerSignupFields`와 서버의 `validateLawyerSignup`으로 처리합니다. 필수 입력 항목은 이름, 아이디, 이메일, 비밀번호, 비밀번호 확인이며 설명 왼쪽에 빨간 별표를 표시합니다. 휴대전화, 변호사 등록 번호, 발급번호, 소속 법무법인/사무소명, 주소, 대표전화는 선택 입력이며 입력한 값만 형식과 길이를 검사합니다. 전문가 그룹 선택과 약관 동의 조건은 유지합니다. 변호사 신분증 이미지 입력은 파일 저장소 준비 전까지 비활성화하며 파일을 전송·저장하지 않습니다.

변호사 가입 정보의 첫 입력란은 필수 항목인 클로즈 베타 가입코드(`betaSignupCode`, 최대 100자)이며 빨간 별표로 표시합니다. 현재 임시 고정 코드는 `1004`입니다. 서버는 앞뒤 공백을 제거한 문자열이 `1004`인 경우에만 신규 가입을 허용하며, 누락·빈 값·다른 코드·문자열이 아닌 값은 `400 INVALID_BETA_SIGNUP_CODE`로 거부합니다. 검증은 비밀번호 해시 생성과 DB 접근 전에 수행하고 실패 시 회원·상세·동의·세션을 생성하지 않습니다. 코드 값은 `expert_accounts.beta_signup_code`에 저장하며 공개 계정 응답에는 노출하지 않습니다. 기존 회원 로그인에는 가입코드를 요구하지 않습니다. 개인정보 동의 문안은 가입코드 필수화에 맞춰 `2026-09-25.4`로 갱신했습니다.

Migration `202609250008_optional_lawyer_signup`은 기존 데이터를 보존하면서 변호사 상세 6개 컬럼을 nullable로 바꾸고 가입코드 컬럼을 추가합니다. 선택 항목의 빈 값은 NULL로 처리합니다. 개인정보 동의 문안은 이 단계에서 필수·선택 항목 구분과 가입코드 수집에 맞춰 `2026-09-25.3`으로 갱신했습니다.

변호사를 선택해 가입하면 상세 정보를 모두 생략해도 `expert_lawyer_profiles`에 회원 ID로 연결된 상세 행을 반드시 생성합니다. 미입력 항목은 NULL로 저장하며, 클로즈 베타 이후에는 같은 행에 정보를 보완할 수 있습니다. 회원·상세·동의 내역은 동일 트랜잭션으로 저장합니다. Migration `202609250009_backfill_lawyer_profiles`는 기존 `LAWYER` 회원 중 상세 행이 없는 회원만 보완합니다. 이미 입력된 상세 정보와 다른 직역·직역 미선택 회원은 변경하지 않습니다.

아이디는 영문으로 시작하는 영문·숫자·밑줄 4~30자이며 소문자로 정규화하여 중복을 차단합니다. 새 회원은 아이디 또는 이메일로 로그인할 수 있습니다. 비밀번호 확인은 서버와 화면에서 일치 여부를 검사하며 저장하지 않습니다. 휴대전화와 대표전화는 하이픈·공백·괄호를 제거한 번호로 저장합니다. 등록번호와 발급번호는 앞자리 0을 보존하는 문자열입니다. 번호 입력은 실제 자격 인증 완료를 의미하지 않습니다.

Migration `202609250004_lawyer_signup`은 회원의 nullable `username`과 별도 변호사 상세 테이블을 추가합니다. 상세 테이블의 현재 이름은 아래 이름 전환 migration을 거친 `expert_lawyer_profiles`입니다. 회원·변호사 상세·동의 내역은 동일 트랜잭션으로 저장하며, 상세 연락처·번호·주소는 공개 계정 응답이나 커뮤니티에 노출하지 않습니다. 기존 회원은 아이디 NULL, 상세 정보 없음으로 유지하고 이메일 로그인을 계속 사용할 수 있습니다. 개인정보 동의 문안은 추가 항목에 맞춰 `2026-09-25.2`로 갱신하며, 이전 동의 기록은 변경하지 않습니다. 다른 직역 개설 시 해당 직역 양식과 검증기를 별도로 추가해야 합니다.

`202609250002_office_signup`은 기존 회원 정보와 비밀번호, 세션, 작성 이력을 수정하거나 삭제하지 않습니다. 기존 회원의 `expert_group`은 NULL, 동의 이력은 없는 상태로 둡니다. 기존 로그인과 이용을 유지하며, 직역 지정·재동의·자격 검증은 이후 별도 절차로 진행합니다. 직역 선택을 검증된 전문가 자격으로 표시하지 않습니다.

### 전문가 이름 통일

Migration `202609250005_expert_naming`은 기존 테이블과 참조 컬럼, 제약조건, 인덱스의 이름을 직접 변경합니다. 적용된 이전 migration 파일은 유지합니다.

| 역할           | 현재 테이블              | Prisma 모델           |
| -------------- | ------------------------ | --------------------- |
| Office 회원    | `expert_accounts`        | `ExpertAccount`       |
| 변호사 상세    | `expert_lawyer_profiles` | `ExpertLawyerProfile` |
| 가입 동의 이력 | `expert_consents`        | `ExpertConsent`       |
| 로그인 세션    | `expert_login_sessions`  | `ExpertLoginSession`  |

검증 답변의 전문가 참조는 DB에서 `expert_id`, 코드에서 `expertId`와 `expert`를 사용합니다. FO 검증 답변 응답의 전문가 정보도 `expert`로 통일하므로 API와 FO를 함께 배포해야 합니다. DB 전환 동안에는 이전 API를 중지하고 migration 적용·Prisma 생성·빌드 후 새 API를 시작합니다.

이름 전환 migration 자체는 회원 ID, 아이디, 이메일, 비밀번호 해시, 동의 원문과 게시글을 보존합니다. 이후 오픈 전 정리 요구에 따라 다음 migration을 추가했습니다.

### 오픈 전 구형 데이터 정리

`202609250006_prelaunch_cleanup`은 로그인 아이디가 없고 변호사 상세·가입 동의도 없는 구형 회원을 삭제합니다. 해당 회원의 로그인 세션, 검증 답변과 연결된 선택·읽음 기록, 커뮤니티 글·댓글도 정리합니다. 현재 양식으로 가입한 회원과 검증 요청 원문은 유지합니다. 삭제된 구형 회원은 현재 가입 양식으로 다시 가입해야 합니다. 위의 기존 계정 보존 설명은 정리 migration 이전 단계의 동작입니다.

전문가별 답변은 `review_contributions`에서 관리하므로 `review_board_posts`의 이전 단일 답변용 `status`, `expert_id`, `reply`, `completed_at` 컬럼을 제거했습니다. 로그인은 `qaver_expert` 쿠키만 인식하며 이전 쿠키 자동 전환 기능을 제거했습니다.

`202609250007_korean_logical_schema`는 모든 업무 테이블과 컬럼에 한글 논리명·설명을 DB 주석으로 저장합니다. [한글 논리 스키마](database-logical-schema.md)와 Prisma의 모델·필드 주석에서도 확인할 수 있습니다.

## 향후 확장과 운영 문안

현재는 전문가 그룹 코드와 신규 가입 정책의 기반만 추가했습니다. 다른 Office를 개설할 때에는 Office별 인증 범위, 질문·검증·커뮤니티 데이터의 그룹 분리와 권한 검증을 함께 구현해야 합니다. 가입 가능 플래그만 변경해서 다른 직역 서비스를 개설하지 않습니다. 자격증·본인확인·관리자 승인 자동화는 이번 범위에 포함하지 않습니다.

약관은 현재 구현된 Free 기능을 기준으로 작성한 기본 문안입니다. 개인정보 수집 목적, 항목, 보유기간, 거부 권리와 불이익을 구분해 기재했습니다. [개인정보 보호법 제15조](https://www.law.go.kr/LSW/lsLinkCommonInfo.do?lsJoLnkSeq=1029334809)와 [제22조 동의 구분](https://www.law.go.kr/lsLawLinkInfo.do?lsJoLnkSeq=900078586&chrClsCd=010202)을 참고했습니다.

운영주체의 정확한 상호·주소와 개인정보 책임자·문의처는 저장소에 제공되어 있지 않아 임의로 만들지 않았습니다. 공개 운영용 최종 문안과 별도 개인정보처리방침에는 이 정보와 실제 위탁·국외이전·파기 및 권리행사 절차를 확정해 반영해야 합니다. 현재의 가입 동의 문안이 이러한 운영 정책 전체를 대체하지는 않습니다.

적용: `npm run db:generate`, `npm run db:migrate` 후 API를 다시 빌드·시작합니다.
