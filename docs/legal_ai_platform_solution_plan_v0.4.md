# AI 법률질문 → 변호사 검증 솔루션
## MVP 제품·기술 통합 기획서

- 문서 버전: v0.4 (FO·BO 업무 구분 반영)
- 수정일: 2026-09-17
- 목적: 사용자용 FO(lawCheck)와 법률사무실 관리용 BO의 업무 범위, 질문 배분, 변호사 인력 관리, 검증·이메일 답변 흐름의 구현 기준을 정의한다.
- 제품 형태: 법률사무실별 전용 사이트를 제공하는 설치·납품형 솔루션
- 기본 스택: React + TypeScript + Vite / Node.js + TypeScript / PostgreSQL + Prisma

## 0. 프로젝트 구분 — FO와 BO

FO와 BO는 사용자와 업무가 다른 두 애플리케이션이다. BO는 법률사무실 관리 시스템을 뜻하며 Backend API 자체를 뜻하지 않는다.

| 구분 | FO — lawCheck | BO — 법률사무실 관리 시스템 |
| --- | --- | --- |
| 사용자 | 홍보 페이지로 들어온 일반 사용자 | 사무실 관리자·업무 담당자·변호사 |
| 핵심 업무 | 비로그인 법률 질문, AI 답변 확인, 질문별 검증 요청 | 검증 요청 접수·배분, 변호사 등록·인력 관리, 답변 처리·발송 관리 |
| 인증 | 익명 세션, 회원가입 없음 | 관리 화면은 직원 계정 로그인·역할 권한 필수 |
| 데이터 범위 | 자신의 익명 세션과 검증 요청 | 소속 사무실의 업무 데이터, 역할별 접근 제한 |
| 업무 종료점 | 선택 질문의 검증 요청 접수 안내 | 변호사 답변 저장 및 사용자 이메일 발송·실패 대응 |

### 0.1 FO — lawCheck

- 홍보 페이지와 법률 채팅 화면을 제공한다.
- GPT API 연동은 서버를 통해 수행하고 질문·AI 답변을 무기명으로 저장한다.
- 사용자는 이미 질문한 항목을 선택하여 이메일과 함께 검증을 요청한다.
- FO는 검증 요청을 접수하고 접수 상태를 안내하는 부분까지 담당한다.
- 변호사 등록·근태·담당자 선택·배분 정책은 FO에 노출하지 않는다.

### 0.2 BO — 법률사무실 관리 시스템

- 사무실 정보와 소속 변호사 정보를 등록·수정·관리한다.
- 입사 예정·재직·퇴사 상태, 입사일·퇴사일, 휴가 기간·승인·취소를 관리한다.
- FO에서 접수된 검증 요청을 업무 목록으로 모으고 담당 변호사에게 배분한다.
- 미배정·배정·검토 중·완료·반려·기한 초과 요청을 관리한다.
- 휴가·퇴사·배정 불가로 남은 미완료 요청을 확인하고 재배정한다.
- 변호사 답변, 이메일 발송·실패·재시도 및 업무 변경 이력을 관리한다.
- 급여·회계 등 추가 사무실 업무는 별도 범위로 정의한다. 현재 인력 관리는 질문 배분에 필요한 입사·퇴사·휴가 관리부터 구현한다.

기존 이메일 URL 답변 흐름은 유지한다. 해당 URL은 BO의 특정 요청 답변 기능만 여는 제한된 접근 경로이며, 직원 관리나 전체 업무 목록에 접근할 수 없다. 변호사 답변용 링크에 별도 로그인이 필요하지 않더라도 BO 관리 화면에는 로그인이 필요하다.

### 0.3 시스템 연결과 프로젝트 구조

```text
FO(lawCheck) → 공통 Backend API → PostgreSQL
BO(사무실 관리) → 공통 Backend API → PostgreSQL
공통 Backend API → GPT API / 이메일 발송 작업
```

초기 구조는 `apps/fo`, `apps/bo`, `apps/api`, `packages/contracts`를 기준으로 한다. 화면·라우팅·권한은 FO와 BO별로 분리하고 공통 API와 DB를 사용한다. FO·BO 분리가 곧 마이크로서비스나 별도 DB를 요구하는 것은 아니다.

FO 검증 요청 저장 시 BO 업무 목록에 같은 요청이 나타나도록 한다. 요청을 별도 DB에 복사하거나 이메일 수신 여부로 접수 여부를 판단하지 않는다. 검증을 요청하지 않은 무기명 채팅은 BO 배분 목록에 포함하거나 변호사에게 자동 공개하지 않는다.

## 1. 확정된 서비스 흐름

```text
변호사가 소속 사무실의 홍보 페이지 URL을 배포
→ 사용자가 홍보 페이지 접속
→ 회원가입·로그인 없이 채팅창에 법률 질문 입력
→ 질문과 AI 답변을 무기명으로 DB에 저장
→ 사용자가 이미 질문한 항목의 [변호사에게 검증 요청] 클릭
→ 해당 질문을 표시하고 답변 수신 이메일 입력
→ "변호사가 검토한 답변을 입력하신 이메일로 보내드립니다." 안내
→ 사용자가 [검증 요청 보내기] 제출
→ 해당 질문의 검증 요청과 수신 이메일을 DB에 저장
→ FO에 접수 안내, BO에 미배정 검증 요청 표시
→ BO에서 재직·휴가·배정 가능 여부를 확인하여 담당 변호사 배정
→ 배정된 소속 사무실 변호사에게 검증 요청 이메일 발송
→ 변호사가 이메일에 포함된 검증 전용 URL 클릭
→ 요청된 질문과 해당 AI 답변 확인
→ 변호사가 답변 작성 후 [답변 전송] 클릭
→ 변호사 답변을 DB에 저장
→ 요청자에게 변호사 답변을 이메일 본문으로 발송
```

위 흐름을 MVP의 단일 구현 기준으로 사용한다. 일반 사용자 회원제 질문 게시판과 전체 채팅 복원은 후순위로 두고, 사무실 업무 관리 화면은 BO 필수 범위로 구현한다.

### 1.1 핵심 규칙

1. 사용자는 회원가입이나 로그인 없이 질문한다.
2. 질문 시 이름·이메일·전화번호를 요구하지 않는다.
3. 질문과 AI 답변은 익명 세션에 연결하여 DB에 저장한다.
4. 사용자가 검증을 요청한 질문에 대해서만 변호사에게 이메일을 보낸다.
5. 검증 요청 시 답변 수신 이메일만 필수로 받는다. 이름은 요구하지 않는다.
6. 요청 대상은 사용자가 선택한 질문과 그 질문의 AI 답변이다.
7. 같은 채팅에 있는 다른 질문은 자동으로 변호사에게 전달하지 않는다.
8. 검증 이메일 수신자는 BO가 배정한 해당 사무실의 재직·활성·승인·업무 가능 변호사로 제한한다.
9. 변호사는 전용 이메일 URL로 접근하여 답변할 수 있다. BO 관리 기능은 별도 직원 로그인과 역할 권한을 적용한다.
10. 답변은 먼저 DB에 저장하고, 저장된 답변을 요청자의 이메일 본문으로 전달한다.
11. 사용자가 답변을 읽기 위해 사이트에 다시 접속할 필요는 없다.

### 1.2 무기명의 의미

무기명 채팅은 사용자 계정이나 실명을 요구하지 않는다는 뜻이다. 질문 본문 자체에는 개인정보가 포함될 수 있으므로 완전히 익명화된 데이터로 취급하지 않는다.

검증 요청 이전에는 연락처를 저장하지 않는다. 검증 요청 이후에는 해당 요청에만 이메일을 저장한다. 이메일을 채팅 세션의 사용자 식별자로 사용하거나 동일 이메일의 여러 대화를 자동으로 합치지 않는다.

## 2. 홍보 페이지와 법률사무실 귀속

- 변호사는 소속 사무실 전용 홍보 페이지 URL을 배포한다.
- 홍보 페이지에는 사무실 소개, 비로그인 법률 채팅, 변호사 검증 안내를 배치한다.
- 사이트 1개는 법률사무실 1개에 귀속된다.
- 서버는 `LAW_OFFICE_CODE`로 현재 사무실을 확정한다.
- 클라이언트가 보내는 사무실 ID로 데이터 귀속이나 수신자를 결정하지 않는다.
- 질문·세션·검증 요청·답변은 모두 현재 사무실 범위에서 조회하고 수정한다.
- 링크를 배포한 변호사 개인을 추적하거나 그 변호사에게 우선 배정하는 기능은 MVP 필수가 아니다.
- 초기 배포는 사무실별 독립 DB를 기본으로 하고, 테이블에는 `law_office_id`를 유지한다.

## 3. MVP 범위

### FO 필수

- 사무실 홍보 페이지와 모바일 대응 채팅 UI
- 비로그인 세션 생성 및 질문·AI 답변 저장
- 법률 질문 여부 분류와 법률 질문에 대한 AI 답변
- 서버 측 질문 횟수 제한
- 질문별 검증 요청 버튼
- 선택 질문 확인 및 답변 수신 이메일 입력 폼
- 검증 요청 저장 및 접수 상태 안내

### BO 필수

- 직원 로그인·권한 및 사무실 설정
- 변호사 등록·정보 수정·승인·활성·메일 수신 설정
- 입사 예정·입사·재직·퇴사 이력 관리
- 휴가 등록·승인·취소·기간별 배정 가능 여부 관리
- 검증 요청 목록·상세·배정·재배정·처리 기한 관리
- 담당 변호사 이메일 알림
- 토큰 URL 기반 변호사 답변 페이지
- 변호사 답변 저장 및 사용자 이메일 본문 발송
- 이메일 재시도와 중복 처리 방지
- 요청·답변·메일 발송 상태의 운영 확인

### 후순위

- 일반 사용자 회원가입·로그인
- 변호사 공개 회원가입 및 고급 개인 통계 대시보드
- 사용자 결과 링크와 전체 채팅 복원
- 채팅 안에 변호사 답변을 추가로 표시하는 기능
- 상담 예약·결제·CRM·변호사 평가
- 파일 업로드·OCR·벡터 검색·고급 판례 검색
- 변호사 개인별 홍보 성과 추적
- 공급사 중앙 관리·라이선스·원격 업데이트

BO의 기본 직원 계정·업무 목록·인력 관리는 필수다. 최초 사무실 관리자를 설치 과정에서 생성하고, 이후 직원 계정과 변호사는 BO에서 관리한다.

## 4. 화면과 사용자 안내

### 4.1 홍보 페이지·채팅

- 사무실명과 연락처
- "로그인 없이 법률 질문을 남겨보세요."
- 질문 입력창, 질문·AI 답변 말풍선, 남은 질문 횟수
- 개인정보를 불필요하게 입력하지 않도록 안내
- AI 답변은 일반 정보이며 변호사 검토 전 답변임을 표시
- AI 답변이 완료된 각 질문 항목에 `[변호사에게 검증 요청]` 표시
- 검증 요청 전에는 변호사에게 질문이 자동 전달되지 않음을 안내

후속 질문의 분류·답변에는 같은 세션의 필요한 이전 문맥을 사용한다. 모델에 전달하는 문맥은 길이를 제한하고 개인정보를 마스킹한다.

### 4.2 질문별 검증 요청 폼

버튼을 누르면 채팅 화면의 패널 또는 모바일 드로어를 연다.

필드와 표시 요소:

- 선택한 질문 및 해당 AI 답변 미리보기
- 답변 수신 이메일: 필수
- 추가 설명: 선택, 앞선 문맥이 필요한 경우 사용자가 직접 보충
- 해당 질문·AI 답변·추가 설명이 소속 사무실 변호사에게 전달된다는 안내
- 수신 이메일로 답변 내용이 전송된다는 안내
- 적용되는 개인정보 처리 안내 및 필요한 동의
- `[검증 요청 보내기]`

안내 문구:

> 변호사가 검토한 답변을 입력하신 이메일로 보내드립니다. 이메일 주소를 정확히 확인해 주세요.

접수 후:

> 검증 요청이 접수되었습니다. 변호사가 답변을 작성하면 입력하신 이메일로 보내드립니다.

버튼 상태는 `검증 요청` → `검증 요청됨` → `답변 작성 완료`로 표시한다. 사용자 메일 발송 상태는 답변 작성 상태와 구분한다.

### 4.3 BO 변호사 답변 페이지

- 사무실명, 선택 질문, 해당 AI 답변, 사용자가 추가한 설명
- 검토 수락 상태와 요청 시각
- 검증 결과 선택: 대체로 타당 / 일부 수정 / 중요 내용 누락 / 추가 사실 필요 / 직접 상담 권장 / AI 답변 부적절
- 답변 내용: 필수
- `[답변 전송]`

답변 전송 시 해당 답변이 사용자 이메일로 전달됨을 명시한다. 다른 질문이나 전체 채팅은 노출하지 않는다.

### 4.4 사용자 답변 이메일

- 제목: `[사무실명] 요청하신 법률 질문에 변호사가 답변했습니다`
- 선택 질문을 식별할 수 있는 최소 설명
- 담당 변호사명·사무실명
- 검증 결과 및 변호사가 작성한 답변 전문
- 사무실 연락처

다른 질문이나 전체 대화는 포함하지 않는다. 질문 원문 전체를 이메일에 반복할 필요는 없다. HTML과 일반 텍스트 본문을 제공하고 사용자·변호사 입력은 안전하게 이스케이프한다.

### 4.5 BO 관리 화면

- `/bo/login`: 직원 로그인
- `/bo`: 미배정·처리 지연·인력 부재·메일 실패 현황
- `/bo/requests`: 검증 요청 목록, 담당자·상태·접수일 필터
- `/bo/requests/:id`: 선택 질문·AI 답변·추가 설명·배정 이력·답변·발송 상태
- `/bo/lawyers`: 변호사 목록, 입사 예정·재직·퇴사 필터
- `/bo/lawyers/:id`: 변호사 정보, 입퇴사 이력, 배정 가능 설정, 미완료 업무
- `/bo/leaves`: 휴가 기간·승인·취소, 영향받는 미완료 업무
- `/bo/staff`: 직원 계정·역할 관리
- `/bo/settings`: 사무실·배분·메일·처리 기한 설정

MVP 역할은 `OFFICE_ADMIN`(인력·계정·설정 관리), `DISPATCHER`(요청 배분·재배분), `LAWYER`(자신에게 배정된 요청 검토·답변)로 구분한다. 역할에 필요한 범위만 조회할 수 있도록 서버에서 검사한다.

퇴사 처리 화면은 효력 시각과 미완료 업무를 함께 표시한다. 휴가 등록 화면은 해당 기간과 겹치는 업무를 보여주고 재배정 필요 여부를 확인할 수 있게 한다.

## 5. 익명 세션과 접근 권한

- 서버가 충분히 긴 랜덤 세션 자격증명을 발급한다.
- 브라우저에는 Secure·HttpOnly·SameSite 쿠키로 보관하고 서버에는 검증용 해시를 저장한다.
- URL이나 요청의 메시지 ID만으로 채팅을 조회하거나 검증을 요청할 수 없다.
- 검증 요청 생성 시 현재 세션 소유권, 메시지의 세션·사무실 귀속, AI 답변 완료 여부를 확인한다.
- 쿠키가 사라진 경우 기존 대화 자동 복원은 MVP에서 제공하지 않는다. 접수된 검증 요청의 이메일 답변은 계속 처리한다.
- 브라우저 세션 만료와 검증 요청 처리 만료는 별도로 관리한다.
- 결과 수신 이메일은 형식 검증과 재확인 UI를 적용한다. 이메일 소유 확인을 도입할지는 공개 운영 정책에서 확정한다.
- 첫 외부 사용자 공개 전 세션·원문·요청·이메일·답변·백업의 보관기간과 삭제 절차를 확정한다.

### 무결성 규칙

- 모든 관계에서 사무실 귀속이 같아야 한다. 복합 외래키 등 DB 제약과 서버 검사를 함께 적용한다.
- 질문·AI 답변·검증 요청은 같은 세션에 속해야 하며, 대상 답변의 부모는 선택 질문이어야 한다.
- `(session_id, sequence_no)`는 유일해야 한다.
- `(verification_request_id, assignment_version, lawyer_id)` 초대는 유일해야 한다.
- 배정 변경과 답변 제출은 동일 요청을 기준으로 직렬화하고 현재 배정 버전을 확인한다.
- 검증 요청별 최종 답변은 하나만 저장한다.
- 검증 요청·답변·발송 기록에 필요한 원문이 보관 중 임의 삭제되지 않도록 삭제 순서를 정한다.

## 7. 변호사 알림·수락·답변 상태

질문 배분의 책임은 BO에 있다. MVP 기본안은 업무 담당자가 배정 가능한 변호사 중 1명을 지정하는 수동 배분이다. 전문분야·미처리 건수 기반 자동 배분은 같은 배정 서비스를 사용하도록 후속 확장한다. 기존 전원 발송·선착순 배정 기본안은 BO 담당자 배정 방식으로 대체한다.

```text
REQUESTED → ASSIGNED → REVIEWING → ANSWERED
ASSIGNED / REVIEWING → REQUESTED (배정 해제)
ASSIGNED / REVIEWING → ASSIGNED (다른 담당자로 재배정)
REQUESTED / ASSIGNED / REVIEWING → EXPIRED
REQUESTED / ASSIGNED / REVIEWING → REJECTED
```

- `REQUESTED`: 요청 저장, BO 배정 대기
- `ASSIGNED`: BO 담당자 배정 완료, 변호사 검토 시작 대기
- `REVIEWING`: 배정된 변호사가 수락하여 검토 중
- `ANSWERED`: 변호사 답변이 저장됨
- `EXPIRED`: 정해진 처리 기한 경과
- `REJECTED`: 처리 불가 또는 검토 반려

이메일 발송 상태는 `email_outbox`에서 따로 관리한다. 메일 실패 때문에 저장된 답변을 미완료로 되돌리지 않는다.

- 이메일 링크 GET 조회만으로 자동 수락하지 않는다. 메일 보안 검사에 의한 링크 조회도 상태를 바꾸지 않아야 한다.
- 배정·메일 발송·링크 접근·검토 수락·답변 전송마다 현재 사무실·재직·휴가·자격·배정 버전·요청 상태를 확인한다.
- 수락은 이미 배정된 담당자가 검토를 시작하는 동작이다. 담당자 변경 권한을 부여하지 않는다.
- 답변 전송은 배정된 변호사만 가능하다.
- 완료 시 해당 요청의 초대를 폐기하고 추가 답변을 차단한다.
- 일시적으로 배정 가능한 변호사가 없으면 요청을 `REQUESTED`로 보관하고 FO에는 배정 대기라고 안내하며 BO에 알린다. 즉시 답변 가능하다고 안내하지 않는다.
- 사무실이 검증 접수를 중지한 경우에는 FO에서 새 검증 요청을 받지 않는다.
- 만료 시간·처리 기한은 설치 설정값으로 두고 공개 운영 전에 확정한다.

### 7.1 입사·휴가·퇴사와 배정

- 입사 예정자는 입사 효력 전까지 배정 대상에서 제외한다.
- 재직 중이고 승인·활성·메일 수신·수동 배정 설정이 유효하며 현재 승인 휴가가 아닌 변호사만 신규 배정 대상이 된다.
- 미래 휴가가 처리 기한과 겹치면 BO 배정 화면에 경고한다.
- 승인 휴가 시작 시 미완료 업무를 배정 대기로 회수하고 기존 링크·검토 세션을 무효화한다. BO 담당자가 다른 변호사에게 재배정한다.
- 휴가 취소·종료 후에는 신규 배정 가능 여부만 다시 계산하고 회수한 요청을 자동으로 돌려주지 않는다.
- 퇴사 효력 발생 시 신규 배정 제외, 연결된 BO 계정·로그인 세션 차단, 답변용 토큰·검토 세션 폐기, 미완료 업무 회수를 처리한다.
- 퇴사자를 삭제하여 과거 답변 작성자나 배정 이력을 없애지 않는다. 이미 완료된 답변은 발송 이력과 함께 유지한다.
- 주기 작업이 입사·휴가·퇴사 효력을 반영하되, 지연되더라도 각 API의 현재 시각 기반 검사가 부적격 접근·배정을 막아야 한다.
- 재배정과 답변 제출이 겹치면 트랜잭션으로 순서를 확정한다. 완료된 요청은 재배정하지 않으며, 배정이 변경된 후 이전 담당자의 제출은 거절한다.
- 재배정·회수 시 이전 초대의 미발송 outbox 작업을 취소한다. 이미 외부로 발송된 메일은 회수할 수 없으므로 해당 URL 접근을 차단한다.

## 8. API — FO·BO 경계

공통 prefix: `/api/v1`

### FO API

| API | 역할·권한 |
| --- | --- |
| `POST /chat/sessions` | 익명 세션 생성, 쿠키 발급 |

| `POST /bo/lawyers`, `PATCH /bo/lawyers/:id` | 관리자의 변호사 등록·정보 관리 |
| `POST /bo/lawyers/:id/employments` | 관리자의 입사·재입사 등록 |
| `PATCH /bo/employments/:id` | 관리자의 입퇴사 효력 관리 |
| `GET /bo/leaves`, `POST /bo/leaves`, `PATCH /bo/leaves/:id` | 관리자의 휴가 등록·승인·취소; 배분 담당자는 필요한 기간·상태만 조회 |
| `GET /bo/staff`, `POST /bo/staff`, `PATCH /bo/staff/:id` | 관리자의 직원 계정·역할 관리 |
| `GET /bo/email-jobs`, `POST /bo/email-jobs/:id/retry` | 관리자·배분 담당자의 발송 실패 확인·허용된 재시도 |
| `GET /bo/settings`, `PATCH /bo/settings` | 관리자의 사무실 설정 |

모든 BO 관리 API는 로그인, 역할, 사무실 범위를 검사한다. FO 익명 쿠키나 답변 링크 토큰으로 호출할 수 없다. 배분 담당자에게 계정 권한 변경이나 인사 정보 전체 조회 권한을 주지 않는다.

검증 요청 body:

```json
{
  "email": "user@example.com",
  "additionalContext": "선택 입력"
}
```

변호사 답변 body:

```json
{
  "resultType": "PARTIALLY_VALID",
  "replyBody": "사용자에게 이메일로 전달할 답변 전문"
}
```

변호사 ID, 수신자 이메일, 사무실 ID는 답변 제출 body에서 받지 않는다. 초대·배정·검증 요청의 서버 저장값으로 결정한다.

사용자에게 보내는 결과 조회 토큰이나 전체 대화 공개 URL은 MVP API에 포함하지 않는다.

## 9. 저장과 이메일 발송의 신뢰성

### 검증 요청 생성

FO는 검증 요청을 `REQUESTED`로 저장한다. 같은 DB의 BO 업무 목록에서 조회되므로 별도 전달 성공 여부에 의존하지 않는다. 배정 전에는 변호사 초대 이메일을 만들지 않는다.

### BO 배정·재배정

하나의 DB 트랜잭션으로 현재 요청 상태·배정 버전·대상 변호사 자격을 확인하고 담당자, 배정 버전, 상태, 배정 이력, 초대, 발송 대기 작업을 저장한다. 재배정 시 이전 초대·검토 세션을 무효화하고 미발송 초대 작업을 취소한다. 커밋 이후 현재 배정에 유효한 이메일만 발송한다.

### 변호사 답변 제출

하나의 DB 트랜잭션으로 담당자·상태를 확인하고 답변 저장, 상태 `ANSWERED` 변경, 사용자 이메일 발송 대기 작업 저장, 초대 폐기를 처리한다.

반복 제출에는 기존 완료 결과를 반환한다. 응답 유실 때문에 사용자가 다시 제출해도 답변이나 발송 작업이 중복 생성되지 않아야 한다.

### 발송 재시도

- 초기에는 PostgreSQL outbox를 읽는 주기 작업으로 구현한다. 별도 Redis 도입은 필수가 아니다.
- 작업을 원자적으로 점유하고, 프로세스 종료 후 점유 기한이 지난 작업은 회수한다.
- 일시 실패에는 제한된 재시도·지연을 적용하고, 최종 실패는 운영자가 확인한다.
- 요청·이벤트·수신자 기반 중복 키를 사용한다.
- 제공자가 지원하면 동일 멱등 키를 사용한다. 외부 전송 성공 후 DB 기록 실패 시 중복 발송 가능성은 남으므로 완전한 단일 배달을 보장한다고 표현하지 않는다.
- 토큰 만료 후에는 만료된 초대 메일을 그대로 재발송하지 않는다.
- 취소되거나 이전 배정 버전의 초대 작업은 재시도하지 않는다. 발송 직전에도 담당자의 재직·휴가·배정 상태를 확인한다.

## 10. AI 처리·질문 제한

```text
입력 검증 및 사용량 확인
→ 질문 저장
→ 개인정보 탐지·마스킹
→ 필요한 이전 문맥을 포함하여 법률 질문 여부 분류
→ 법률 질문이면 AI 답변 생성
→ 질문과 연결된 답변 저장
→ 화면 표시
```

- 최초 외부 모델 호출 전에 마스킹한다.
- 비법률 질문은 안내 메시지를 반환한다.
- 분류가 불확실하면 추가 설명을 요청한다.
- AI 실패는 재시도 가능한 상태로 저장하며 원문 오류·stack trace를 노출하지 않는다.
- AI 답변 완료 전에는 검증 요청 버튼을 활성화하지 않는다.
- 근거를 확인하지 못한 판례번호·조문 인용을 생성하여 표시하지 않는다.
- 법령 데이터 연동을 추가할 때 출처·조회 시각·법령 버전을 저장한다. 검색 연동 전에는 확인되지 않은 구체적 인용을 표시하지 않는다.

MVP 질문 제한 기본값은 세션당 3회로 둔다.

개발 중에는 `QUESTION_LIMIT_ENABLED=false`로 횟수 제한을 임시 비활성화한다. 오픈 시 `true`로 변경하여 세션당 3회 제한을 적용한다.

- 유효한 신규 입력 접수 시 원자적으로 차감한다. 비법률 질문도 분류 비용이 발생하므로 포함한다.
- 네트워크 재시도는 같은 요청 키를 사용해 중복 차감·생성을 막는다.
- 서버·모델 실패 후 동일 질문 재처리는 추가 차감하지 않고 재시도 횟수를 제한한다.
- 세션 신규 생성, 질문, 검증 요청, 이메일 발송에도 각각 요청 속도 제한을 적용한다.
- 사무실별 일일 비용 상한과 AI 호출 중단 설정을 둔다.

## 11. 최소 보안·운영 기준

- HTTPS, 서버 측 API 키 관리, 최소 DB 권한
- 세션·토큰 해시 저장, 초대 만료·폐기, 토큰 URL 로그 마스킹
- 검토 토큰은 요청·변호사·사무실에 묶고 권한을 해당 요청으로 제한
- 검토 링크를 제한된 쿠키 세션으로 교환한 후 주소창에서 토큰 제거
- 검토 페이지에 외부 분석 스크립트를 넣지 않고 캐시·리퍼러 노출 제한
- 쿠키 기반 변경 요청에 CSRF 방어 및 입력 검증
- 사용자·모델·변호사 텍스트의 HTML 이스케이프
- BO 직원 인증·역할·사무실별 권한, 등록 변호사의 재직·휴가·승인·활성 여부 확인
- 개인정보 처리 안내, 이메일 오입력 대응, 보관기간·삭제·백업 복구 절차
- 비용·AI 실패·이메일 실패·검증 지연 모니터링

공개 운영 전에 미확정할 수 없는 항목: 개인정보 처리 고지·동의 방식, 보관기간, 이메일 소유 확인 적용 여부, 검증 처리 기한, 초대·세션 만료 시간, 메일 재시도 한도, 사무실 비용 상한.

## 12. 개발 순서

1. 공통 기반: FO·BO·API 프로젝트 분리, DB·사무실 설정·공통 계약
2. FO: 홍보 페이지·익명 세션·채팅 저장·질문 제한
3. FO: 마스킹·법률 분류·AI 답변·실패 처리
4. FO: 질문별 검증 폼·이메일 수집·소유권 검사·접수 완료
5. BO: 직원 인증·권한·변호사 등록·입사·퇴사·휴가 관리
6. BO: 검증 업무 목록·배정·회수·재배정·이력
7. BO: 초대·outbox·변호사 이메일·토큰 검토·답변 저장
8. BO: 사용자 답변 이메일·재시도·효력 반영 작업·운영 현황
9. FO·BO 통합: 권한·동시성·인력 변경·실패 시나리오 검증 및 공개 배포

FO를 먼저 개발하되 공개 서비스의 검증 요청부터 답변까지 완료하려면 BO 배분·답변 기능까지 연결되어야 한다. 보안과 권한 검사는 각 기능을 만드는 단계에 함께 구현한다.

## 13. MVP 완료 기준

다음 시나리오를 모두 확인한다.

1. 홍보 URL에서 로그인 없이 질문하고 질문·AI 답변이 DB에 저장된다.
2. 질문만 하고 검증을 요청하지 않으면 변호사 이메일은 발송되지 않는다.
3. 질문 여러 개 중 하나를 선택하면 그 질문·AI 답변·추가 설명만 검증 요청에 담긴다.
4. 검증 폼은 이름 없이 이메일로 제출할 수 있다.
5. 다른 세션의 답변 ID로 검증 요청을 만들 수 없다.
6. 다른 사무실 변호사에게 초대가 생성되거나 전달되지 않는다.
7. 초대 URL로 로그인 없이 해당 요청을 검토할 수 있다.
8. BO에서 동시에 배정·재배정해도 현재 담당자는 한 명만 확정된다.
9. 만료·폐기·이전 배정 토큰, 미승인·비활성·휴가·퇴사 변호사, 비담당자의 답변 제출은 거절된다.
10. 답변 전송 시 DB에 답변이 저장되고 사용자에게 그 답변 전문이 이메일로 발송된다.
11. 사용자에게 사이트 재접속이나 결과 URL 클릭을 요구하지 않는다.
12. 이메일 장애·프로세스 재시작 후에도 저장된 발송 작업을 복구할 수 있다.
13. 중복 요청·답변 제출로 검증·답변·발송 작업이 중복 생성되지 않는다.
14. 비법률 질문, 문맥 의존 후속 질문, AI 실패, 질문 한도 초과를 처리한다.
15. 세션 쿠키가 사라져도 이미 접수된 요청의 답변 이메일은 처리된다.
16. FO에서 검증 요청을 접수하면 BO의 미배정 업무 목록에 나타나고, 요청하지 않은 다른 채팅은 나타나지 않는다.
17. 입사 예정자는 효력 전 배정되지 않으며 입사 후에도 승인·활성 조건을 만족해야 한다.
18. 승인 휴가 기간에는 신규 배정을 막고 미완료 업무를 회수한다. 휴가 종료·취소가 수동 중지나 퇴사 상태를 해제하지 않는다.
19. 퇴사 효력 발생 시 BO 계정·세션·답변 링크를 차단하고 미완료 업무를 회수하며 과거 답변 이력은 보존한다.
20. 재배정 후 기존 변호사 링크는 사용할 수 없고 이전 초대 메일의 대기·재시도 작업은 취소된다.
21. 담당자 부재 시 미배정 업무를 보관하고 FO에 배정 대기 상태를 안내한다.
22. FO 익명 세션·답변용 토큰·다른 사무실 직원으로 BO 인력·배분 관리 기능에 접근할 수 없다.
23. 휴가·퇴사 효력 반영 작업이 지연돼도 현재 시각 기반 API 검사가 부적격 배정·답변 제출을 차단한다.

## 14. 핵심 지표

- 홍보 페이지 방문 → 첫 질문 비율
- AI 답변 완료율
- AI 답변 확인 → 질문별 검증 요청 비율
- 검증 요청 → 변호사 답변 완료율
- 요청부터 답변까지 걸린 시간
- 변호사 초대·사용자 답변 이메일의 발송 실패율
- 사무실별 AI 비용과 미처리 검증 건수
- BO 미배정 대기 시간, 변호사별 미완료 건수, 휴가·퇴사로 인한 재배정 건수

MVP의 제품 검증 질문은 "홍보 페이지로 들어온 사용자가 법률 질문을 하고, 특정 질문에 대한 변호사 답변을 이메일로 받으려 하는가?"이다.
